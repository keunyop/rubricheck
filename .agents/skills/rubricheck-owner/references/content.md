# 콘텐츠와 유입 개선

기존 `doc/seo` 기록과 `src/config/blog.ts`, `app/blog`, sitemap, 현지화 route를 확인하고 기존 형식을 따른다. 실제 위치가 바뀌면 검색으로 다시 확인한다.

1. GSC/GA4가 있으면 브랜드/비브랜드·페이지·국가·기기·의도·첫 사용 전환으로 기회를 좁힌다. 없으면 코드/기존 문의 근거의 가설로 표시한다.
2. 대상 독자, 해결할 질문, 검색 의도, 기존 글과 차이, 실제 기능 연결, 자연스러운 CTA를 먼저 정의한다. 새 글보다 기존 글 제목/설명/내부 링크 개선이 나은지 판단한다.
3. 완성된 본문·slug·title·meta description·관련 링크를 준비한다. 바로 사용할 수 있는 예시/rubric을 포함하고 가격·기능·외부 사실은 출처를 확인한다. 대량 유사 글, 허위 후기, 검증되지 않은 효과는 금지한다.
4. 링크·render·모바일·canonical/hreflang/sitemap/robots 및 구조화 데이터를 변경 범위에 맞춰 검증한다. 사용자 과제·결과·계정·admin을 검색 공개 대상으로 추가하지 않는다. robots는 접근 통제가 아니다.
5. 게시 승인 상태, 실제 게시일, 7일 색인 확인·28일 검색/첫 사용 검토일을 `doc/operations/experiments.md`에 남긴다. 미게시면 게시일과 성과는 null이다. 운영 게시 위임이 없으면 검증한 초안까지만 완료한다.

특정 국가 방문 비중만으로 번역을 결정하지 않는다. 저표본에서는 정성 사례와 실제 사용/전환을 함께 보고 복잡한 A/B 인프라부터 만들지 않는다.
