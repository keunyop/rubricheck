# GA4 measurement drop reported October 28, 2026

The owner reported near-zero traffic beginning October 23. The October 22 release changed GA4 from page-load collection to explicit opt-in collection. An isolated browser confirmed that the existing GA4 property (`G-S7M12R54DP`) still generated a sanitized page view after consent, and the production `NEXT_PUBLIC_GA4_MANUAL_PAGEVIEWS` setting remained `true`. This was not a disabled production setting or a broken Google command queue.

Two problems were reproduced against production before the repair:

- At a 390 × 844 mobile viewport, the English pricing page's consent button was at y=2072.39. New visitors could not see either consent choice without scrolling to the footer. This provides a likely explanation for the sharp reduction after opt-in collection was introduced; daily consent rates and GA4 report ingestion were not independently available to quantify it.
- With consent already granted, `/pricing` loaded the Google tag while `/hi/pricing` did not. The public-path filter only recognized Korean and Malay locale prefixes, excluding Hindi, Urdu, Vietnamese and Simplified Chinese from GA4, Vercel Analytics, Speed Insights and first-party page/pricing events after the localization release.

The repair makes the initial consent choices visible at the bottom of the viewport, gives accept/refuse the same button styling, and keeps the existing footer preference control after a decision. It reads the saved choice after hydration. The public-path filter now uses the application's shared locale parser so all seven languages retain the existing public-path allowlist.

Explicit consent, existing refusals, DNT/GPC, private-route suppression and removal of URL queries/fragments are preserved. The change does not backfill visits that were never sent, and counts remain limited to consenting visitors. Comparisons with the period before October 22 must account for the measurement policy change.

## Verification

`scripts/check_ga4.mjs` tests the initial choice visibility on mobile/desktop, refusal, DNT/GPC, opt-in, real gtag.js payloads, client navigation, all seven public language variants, withdrawal and private billing-route exclusion. First-party API calls and Vercel collection are intercepted to avoid synthetic cohort data. Google collection is also intercepted by default; `GA4_VERIFY_DELIVERY=true` permits exactly one verification page view to reach Google. A 2xx collection response confirms transport, not inclusion in the GA4 reporting UI.

Run a production build with `NEXT_PUBLIC_GA4_MANUAL_PAGEVIEWS=true`, start it locally, then run `npm run test:ga4:browser` with `TEST_BASE_URL` pointing to that server. The script uses the existing Playwright installation or `PLAYWRIGHT_MODULE` and writes local evidence under the ignored `.growth-local/` directory.

Pre-release results: 12 targeted analytics tests passed; focused ESLint and the optimized Next.js build (including TypeScript) passed. All 14 browser checks passed against the local production build with real gtag.js and all analytics delivery intercepted. Mobile and desktop screenshots confirmed that both initial choices fit in the viewport. The browser withdrawal check waits for the hydrated preference control after reload instead of depending on background vendor requests reaching network idle.
