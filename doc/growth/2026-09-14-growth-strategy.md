### 5순위. 실제 성적과 코멘트 등록

과제를 마친 뒤 “실제 점수와 코멘트 추가”를 제공한다.

- 기존에 채점한 과제를 클릭해서 불러옴.
- 실제 점수와 과제에 대한 코멘트를 등록할수 있음.
- 점수와 코멘트 등록시 본인 기록, 서비스 품질 검증 동의, 외부 사례 공개 동의를 구분.
- 당시 AI 추정과 실제 결과 차이를 확인.

**유지 가치:** 과제 이후에도 돌아올 이유를 만든다. 장기적으로 과목별 반복 약점을 보여줄 수 있다.

**신뢰 가치:** 현재 갤러리 2개를 넘어, 동의받은 실제 사례와 실패 사례를 함께 설명할 기반이 된다. 분석에는 과제 유형별 오차·범위 포함률·반복 실행 변동을 사용한다. 단순 상관계수나 일부 성공 사례만으로 정확도를 홍보하지 않는다.
표본이 적을 때는 참고 코멘트로 사용하고 자동 점수 보정을 서두르지 않는다. 모델·프롬프트를 바꿀 때는 따로 보관한 검증 과제로 확인한다.

### 6순위. 튜터·스터디 그룹용 소규모 워크스페이스

후속 확장 후보는 과외 교사·라이팅 튜터다.

- 튜터가 루브릭을 배포하고 학생이 자기 초안을 사전 점검.
- 튜터가 허용된 결과를 보고 가장 중요한 문제에 코멘트.
- 초대·활성 학생·공통 약점을 보는 작은 대시보드.
- 학생 수 또는 포함 평가량을 기준으로 별도 상품을 검증.

처음부터 학교 전체 LMS를 만들면 판매·권한·데이터·운영 범위가 크게 늘어난다. 먼저 소수 튜터의 실제 사용과 지불 의사를 확인한다. 학생 Pro 무제한 상품에 대량 채점 비용을 그대로 포함하지 않는다.

## 6. 경쟁 제품을 고려한 포지셔닝

[Grammarly 공식 AI Grader 안내](https://support.grammarly.com/hc/en-us/articles/38552360525837-AI-Grader-user-guide)는 루브릭·과제 정보 기반 피드백, 문단별 제안, 점수 추정, 기본 기준 검토와 Free의 하루 1회 제한 검토를 설명한다. 따라서 “AI가 루브릭으로 채점한다”는 기능만으로 독점적인 차별성을 주장하기 어렵다.

[EssayGrader 공식 가격 안내](https://www.essaygrader.ai/pricing)는 교육자 중심으로 루브릭 라이브러리, 글쓰기 성장 추적과 LMS 연결을 판매한다. 교사 시장은 학생 시장과 구매 이유가 다르며, 그 무료 횟수나 가격을 RubriCheck에 그대로 적용할 근거는 없다.

권장 약속:

> 제출 전에 내 루브릭에서 놓친 부분을 찾고, 수정본이 어떻게 달라졌는지 확인한다.

세부 경쟁력은 **빠른 시작, 내 루브릭의 정확한 해석, 원문에 연결된 근거, 반복 수정 기록, 실제 피드백으로 확인되는 신뢰**에서 검증해야 한다. 이것들이 다른 제품에 전혀 없다고 주장하는 것은 아니다.

## 7. 가격과 유료 가치 설계

현재 운영 UI에서 직접 확인한 가격:

| 상품 | 표시 가격 | 현재 핵심 제공 |
|---|---:|---|
| 무료 | 0 | 총 3회 체험, 기본 피드백과 우선순위 일부 |
| Pro 월간 | $7.99/월 | 무제한 평가, Strict, 상세 피드백, 재작성 제안 |
| Pro 연간 | $59.99/년 | 같은 Pro 기능, UI에서 약 37% 절약 안내 |
| 충전 | 10회 $4.99 / 25회 $9.99 / 60회 $19.99 | 평가용, Strict·상세 결과, 재작성 제외 |

가격 표시는 [운영 가격 페이지](https://rubricheck.com/pricing)와 캡처 기준이며, 실제 결제 통화·세금·Stripe 청구 설정을 별도로 확인한 것은 아니다.

권장 원칙:

1. 가격부터 낮추지 않는다. 입력 유실·첫 체험·구독 가치·전환 계측을 먼저 개선한다.
2. Free는 좋은 피드백을 믿을 수 있게 만드는 체험, Top-up은 가끔 있는 과제, Pro는 학기 동안 반복 수정·과목별 관리로 설명한다.
3. Pro의 차이를 “무제한”보다 “이전 과제부터 다음 과제까지 이어지는 수정 기록과 코칭”으로 보여준다.
4. 가격 페이지에 Free/Top-up/Pro의 차이와 실제 결과 예시를 함께 제공한다. 현재 탭을 오가며 비교해야 하는 부담을 줄인다.
5. 동일 과제의 단순 재열람·결제 후 복구는 새로운 평가 구매로 취급하지 않는 방향을 검토한다. 신규 재평가와 상세 추가 분석의 차감 규칙은 명확히 보여준다.
6. 학기권·일시정지는 실제 해지 사유에서 방학·학기 종료가 자주 나올 때 검증한다. `semester`라는 내부 plan 값이 있지만 현재 공개 결제 선택지는 월간·연간이다. 처음부터 상품 수를 더 늘릴 이유는 약하다.
7. 60회 충전이 일부 사용자에게 긴 기간 충분할 수 있다. 이것이 구독을 잠식하는지, 원래 구독하지 않을 사용자의 추가 매출인지 코호트별 매출·비용·후속 전환으로 구분한다.

Pro가 무제한인 만큼 수익은 결제 건수만으로 판단할 수 없다. 성공·실패 평가의 입력/출력 사용량, OCR, 재시도, 저장 비용을 기록한다. 기존 7일 루브릭 구조화 캐시는 이미 있으므로 이를 새 기능처럼 제안하지 않는다. 버전 보관으로 중복 분석을 줄이는 방향을 검토한다.

## 8. 6–8주 실행 순서

개발자 1명이 기존 스택을 잘 안다는 가정의 실행 초안이다. 특히 계정별 저장과 파일 관리가 예상보다 크면 1순위 기능을 더 작게 나눈다.

### 1주차: 전환 동선과 기준선

- 입력 유실 해결, 무료 실패 반환 정책 정리.
- 핵심 이벤트와 평가 비용 기록.
- 홈 상단 무료 범위, 첫 결과 예시, 가격 비교 개선.
- 실제 사용자 5명 정도와 자발적 사용 관찰을 모집할 계획 수립. 이번 분석에서 연락하거나 인터뷰하지 않았다.

### 2–3주차: 첫 체험과 과제 저장

- 미리 계산한 예시 체험.
- 계정별 과제 1개 저장, 입력·루브릭 재사용.
- 현재 과제를 보존하는 업그레이드 복귀.
- 무료 3회를 초안→수정본→최종 점검으로 안내.

### 4–6주차: 수정 전후 비교 MVP

- V1/V2 저장과 기준별 비교.
- 개선 체크리스트와 해결 여부.
- Pro의 여러 과제·장기 이력 구분.
- 같은 조건의 평가 안정성 검증.

### 7–8주차: 검증된 사용 흐름 확대

- 루브릭 시작 링크와 유입 측정.
- 실제 성적 추가의 작은 입력 화면.
- 지표를 보고 루브릭 없는 시작 기능, 문단 코칭, 튜터 파일럿 중 하나를 선택.

**3개만 구현한다면:** 입력을 보존하는 로그인 전 예시 체험, 과제별 저장, 수정본 비교. 이 세 가지로 첫 체험·반복 사용·구독 이유를 함께 검증한다. 계측은 세 기능 모두에 포함한다.

## 9. 성공을 판단하는 방법

성장 구조:

`관련 방문 → 첫 평가 완료 → 실제 수정·재평가 → 다음 과제 사용 → 유료 전환 → 갱신`

현재 자료만으로 가장 큰 이탈 구간을 확정할 수 없다. 아래 순서로 기준선을 만든다.

| 목표 | 주 지표 | 함께 확인할 지표 |
|---|---|---|
| 사용자 증가 | 주간 첫 평가 완료 사용자 | 방문 경로, 첫 평가 시간·오류, 획득 원가 |
| 제품 가치 | 동일 과제 7일 내 재평가 사용자 비율 | 실제 수정 여부·유용성 피드백 |
| 반복 사용 | 첫 평가 사용자 중 30일 내 두 번째 과제 사용자 비율 | 학기·국가·과제 유형 |
| 구독 전환 | 첫 평가 후 14일 내 신규 Pro 비율 | paywall→checkout→결제 성공 |
| 유지 | 유료 2개월차 유지율 | 해지 이유, 학기권·방학 영향 |
| 수익성 | 코호트별 매출−변동 비용 | 모델/OCR·결제 수수료·환불·지원 비용 |

무료 체험 확대는 첫 평가 완료를 늘려도 결제나 기여이익을 떨어뜨릴 수 있다. 추천 보상도 가입 건수 대신 실제 사용과 비용을 본다.

최근 검색 클릭 424회/28일만 보면 여러 A/B 실험을 동시에 돌려 구독 차이를 확정하기에는 표본이 적을 가능성이 높다. 전체 유입을 먼저 확인하고, 초기에는 한 가지 변화씩 사용성 관찰과 코호트 데이터를 모은다. 짧은 기간의 몇 건 차이를 확정적 개선으로 선언하지 않는다. 학사 일정과 이미 존재하던 검색 증가 추세도 기록한다.

MRR은 월간 구독과 연간 구독을 월 기준으로 환산해 계산한다. 충전 매출은 별도 일회성 매출로 보고, 이를 MRR에 섞지 않는다. 원가가 확인되기 전에는 구체적인 매출 상승률이나 안정적인 마진을 예측하지 않는다.

## 10. 지금은 뒤로 미룰 기능

- **전면 자동 에세이 작성:** 현재의 검토·수정 가치를 흐리고 일반 생성 도구와 비교되기 쉽다. 원문에 근거한 코칭부터 검증한다.
- **일반 챗봇:** 과제·기준·원문·수정 이력에 연결되지 않은 대화는 추가 구독 이유가 약하다.
- **독립 AI 탐지·Humanizer:** 코드의 Hidden AI text 경고는 문서 내 지시문 경고다. 일반적인 AI 작성 여부 탐지로 홍보할 근거가 없으며 성장 주력 기능으로 확대하지 않는다.
- **네이티브 모바일 앱:** 웹 입력과 재사용이 먼저다. 사진 입력은 이미 있다.
- **대규모 LMS·학교 영업:** 개인 학생의 반복 사용과 작은 튜터 수요를 먼저 검증한다.
- **많은 언어·시험별 페이지:** 영어 검색 의도에서 실사용 전환을 만든 후 실제 수요로 확장한다.
- **상품·할인 종류 확대:** 월간·연간·충전이 이미 있다. 지속적인 제품 가치와 명확한 비교를 먼저 만든다.

## 12. 이번 분석의 산출물

애플리케이션 기능이나 결제 정책은 변경하지 않았다. `doc/growth/`에 보고서, 공개 사이트 확인 스크립트, 캡처와 재집계 자료를 추가했다. 브라우저 스크립트는 이 PC에 설치된 Playwright 패키지를 찾아 사용하는 분석용 도구이며 제품 실행 의존성은 아니다.

검증: 공개 UI·6개 안내 페이지·요금제 탭·모바일 가로 넘침 없음 확인, 입력 유실 재현, 원본 검색 통계 재계산, 점수 후처리 합성 데이터 검증. 인증 이후 전체 평가와 실제 결제 완료 흐름은 실행 검증하지 않고 코드로 검토했다.
