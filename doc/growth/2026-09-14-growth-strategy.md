## 4. 기능 개발 전 먼저 해결할 항목



### P0-4. 점수 신뢰성과 유료 경계를 정리한다

- 현재 전체 점수 후처리는 Standard에서 +4점, Strict에서 -3점이다. 같은 합성 기준별 범위 합계 70–80을 넣었을 때 74–84와 67–77을 반환했다. 실제 AI 정확도 실험은 아니다.
- 따라서 모드 변경에 따른 차이를 수정 효과로 보여주면 안 된다. 실제 채점 자료로 보정의 타당성을 검증하고, 항목 합계와 전체 점수 차이를 설명할 수 있게 한다.
- 폭이 5 이하인 추정 범위를 UI에서 단일 점수로 보여주는 코드도 있다. 데이터로 보정된 신뢰구간과 단순 출력 범위를 구분한다.
- 무료 API 결과에는 `top_improvements` 3개가 모두 들어가고 화면에서 1개만 표시된다. 유료 경계를 유지할 항목은 서버 응답에서도 일치시킨다. 또는 전체 개선점을 무료로 제공하고 반복 수정·저장을 유료 가치로 이동한다.

근거: [점수 처리](../../lib/gradeFinalization.ts), [합성 검증](evidence/scoring-calculation.json), [무료 표시 정책](../../src/lib/accountFeatureAccess.ts).

## 5. 추천 기능 우선순위

영향은 현재 자료에 기반한 정성적 판단이다. 개발 난도는 기존 코드를 잘 아는 개발자 1명의 MVP 기준이며, 실제 일정 견적은 아니다.

| 순위 | 기능 | 사용자 증가 | 구독·유지 | 개발 난도 | 판단 |
|---|---|---|---|---|---|
| 1 | 과제별 수정 작업공간·버전 비교 | 중간 | 매우 높음 | 중상 | 주력 유료 가치 |
| 2 | 로그인 전 예시 체험·첫 과제 완주 | 높음 | 높음 | 낮음~중간 | 첫 체험 개선 |
| 3 | 루브릭 저장·재사용·읽기 확인 | 높음 | 높음 | 중간 | 반복 입력 비용 제거 |
| 4 | 공유 가능한 루브릭·과제 시작 링크 | 높음 | 중간 | 중간 | 제품 사용에서 생기는 유입 |
| 5 | 실제 성적·교수 피드백 연결 | 중간 | 높음 | 중상 | 신뢰·장기 유지 강화 |
| 6 | 튜터용 소규모 그룹 | 중간 | 높음, 별도 고객군 | 높음 | 수요 검증 후 확장 |

### 1순위. 과제별 수정 작업공간과 버전 비교

**사용자가 얻는 가치:** “이 과제의 어디를 고치고, 무엇이 나아졌는지 알 수 있다.”

권장 흐름:

1. 과제 이름·루브릭·초안으로 작업공간을 만든다.
2. 결과에서 기준별로 관련 원문 문장을 강조한다.
3. 개선 항목을 누르면 수정 이유·필요한 근거·확인 질문을 보여준다.
4. 사용자가 수정본을 붙여넣거나 파일로 올린다.
5. 같은 루브릭과 평가 조건으로 재평가하고 이전 버전과 비교한다.
6. 해결된 누락, 남은 문제, 새로 생긴 문제를 표시한다.

예: “Evidence 기준에서 주장과 출처 연결이 빠져 있음 → 문단 수정 → 근거 연결은 개선되었지만 반론 검토는 남음.” 이 흐름은 단순한 점수보다 다음 행동을 분명히 한다.

**MVP 범위:** 같은 과제 V1/V2 보관, 기준별 결과 비교, 개선 체크리스트, 수정본 재업로드. 처음부터 복잡한 문서 편집기를 만들 필요는 없다. 문단 강조와 부분 수정 제안은 다음 단계로 추가한다.

**무료와 유료:** 무료 사용자는 과제 1개에서 실제 수정→재평가를 체험하게 한다. Pro는 여러 과제, 장기 이력, 과목별 약점, 반복 코칭을 제공한다. 기본적인 데이터 다운로드·삭제를 결제 조건으로 묶지 않는다.

**구독 이유:** 사용자가 매 과제마다 돌아올 이유와 학기 전체의 기록이 생긴다. 지금의 무제한 평가·짧은 재작성 제안보다 지속적 가치를 설명하기 쉽다는 가설이다.

**기술 포인트:** `assignments`, `rubric_versions`, `evaluation_runs`, `revision_tasks` 같은 영구 데이터가 필요하다. 루브릭 버전·mode·모델·프롬프트 버전을 기록한다. 기존에는 결제 중심 식별자가 많으므로 검증된 사용자 ID와 과제 소유권을 명확히 연결한다. 분석 결과의 복원은 서버의 소유권·권한 확인을 거친다.

점수 상승을 강제로 만들지 않는다. 입력이 같으면 결과 재사용을 검토하고, 조건이 달라졌으면 비교에 표시한다. “성적 향상”과 “AI가 추정한 범위 변화”도 구분한다.

**성공 지표:** 동일 과제 재평가율, 30일 내 두 번째 과제 생성, 실제 수정 후 유용성 평가, 재평가 경험자와 미경험자의 구독·유지 차이. 마지막 차이는 선택 편향이 있어 인과효과로 바로 해석하지 않는다.

### 2순위. 로그인 전 예시 체험과 첫 과제 완주

**관찰:** 현재 첫 평가부터 이메일 인증이 필요하다. 홈 상단에는 파일 두 개와 실행 버튼이 있고, 무료 3회 안내는 FAQ에 있다. 결과를 보기 전 해야 할 일이 많다.

첫 구현:

- 상단에 “3 free checks · No card required”를 명시한다.
- “Try a sample”로 짧은 에세이+루브릭+결과를 즉시 열어준다. 예시라고 명확히 표시하고 미리 저장한 결과를 사용해 호출 비용을 줄인다.
- 결과의 한 기준에 대해 원문→문제→수정 예시→재확인까지 체험하게 한다.
- 자기 과제로 바꿀 때 입력을 유지하며 가입한다. 인증 완료 후 원래 하던 행동으로 자연스럽게 이어진다.

그다음 실험:

- 로그인 전 본인 과제 1회 제한 평가와 현재 인증 우선 흐름을 비교한다. 요청·길이·비용 제한을 갖춘 경우에만 범위를 넓힌다.
- 별도 대규모 무료 사용량 확대보다, 현재 무료 3회를 “초안→수정본→최종 점검”으로 안내한다.
- 첫 평가에만 상세 기준 1개 또는 전체 상세 분석 1회 체험을 제공할지 실험한다. 결제 뒤 받게 될 가치를 구체적으로 보여주는 목적이다.

**성공 지표:** 첫 평가 완료율과 시간, 첫 수정 행동, 첫 평가 후 14일 내 구독 전환, 신규 활성 사용자당 비용. 가입 수만 늘고 결과를 보지 않는다면 성공이 아니다.

### 3순위. 내 루브릭 보관함과 과제 지시문 해석

현재 사용자는 매번 루브릭을 준비해야 한다. 서버에는 7일 루브릭 구조화 캐시가 있지만, 사용자가 찾아 재사용하는 보관함은 없다.

우선 구현:

- “이 루브릭 저장”, 최근 루브릭 선택, 과목 이름 붙이기.
- 파일에서 읽어낸 기준·배점·합계를 평가 전 확인하고 수정하기.
- 과제 지시문을 선택적으로 추가해 단어 수·필수 섹션·출처 개수 같은 명시적 요구를 체크리스트로 보여주기.
- 루브릭과 지시문이 한 파일에 있을 때 구분 추출하기.

루브릭이 없는 방문자:

- 에세이·보고서·성찰문용 시작 템플릿 또는 지시문 기반 체크리스트를 제공한다.
- 교사가 제공한 루브릭이 없는 경우 “일반 기준 검토”로 명시하고, 교사의 성적을 예측하는 것처럼 표시하지 않는다.
- 생성된 기준을 확정하기 전에 사용자가 검토하게 한다.

**유입 연결:** 실제 검색 수요가 관찰된 에세이 페이지에 이 시작 기능을 연결한다. 현재 6개 설명 페이지를 실사용 경로로 강화하고, 많은 유사 SEO 페이지를 한꺼번에 만들지 않는다.

**수익 연결:** 무료에는 소수 루브릭 저장과 기본 요건 확인, Pro에는 과목별 보관함·여러 과제 재사용·과목별 약점 추적을 배치한다.

스캔 PDF의 자동 OCR 대체 처리, 짧은 루브릭을 과도하게 거절하지 않는 입력 검증도 활성화 관점에서 유효하다. 현재 PDF는 텍스트 추출만 하며, PDF/DOCX/단일 이미지의 의미 있는 텍스트 검증은 200자 기준이다. 실제 업로드 오류 유형을 먼저 보고 우선순위를 정한다.

### 4순위. 과제 본문을 공유하지 않는 루브릭 시작 링크

현재 PNG 공유가 있으므로 “공유 기능 추가”라는 설명은 부정확하다. 필요한 것은 공유받은 사람이 제품 사용으로 이어지는 경로다.

- 루브릭과 빈 과제 공간만 포함한 “Use this rubric” 링크.
- 같은 수업 친구가 열면 자기 초안을 넣고 바로 시작.
- 작성자가 원할 때만 선택한 결과 요약을 공유. 기본값에서 초안과 성적은 제외.
- 링크 취소·공개 범위와 간단한 미리보기를 제공.
- 공유 링크를 거쳐 첫 평가를 완료한 사용자를 측정.

친구 초대 보상은 초대한 사람 수보다 **새 사용자의 첫 유효 평가 완료**에 연결한다. 초기에 작은 평가 크레딧 보상과 상한을 실험하고, 보상이 만든 실제 활성 사용자당 원가를 본다. 이미 있는 크레딧 장부를 활용할 수 있지만 자기 추천·반복 계정 보상은 제한해야 한다.

**공유 이유:** 낮은 자기 점수를 공개하는 것보다 “우리 수업 루브릭으로 바로 확인해 봐”가 자연스러울 가능성이 높다는 제품 가설이다. 루브릭 공유 권한과 공개 범위를 사용자가 통제할 수 있게 한다.

### 5순위. 실제 성적과 교수 피드백 연결

과제를 마친 뒤 “실제 점수와 코멘트 추가”를 제공한다.

- 어떤 버전을 제출했는지 지정.
- 실제 기준별 점수와 총점을 기록.
- 당시 AI 추정과 실제 결과 차이를 확인.
- 다음 과제에서 사용자가 제공한 교수 코멘트를 참고할 수 있게 함.
- 본인 기록, 서비스 품질 검증 동의, 외부 사례 공개 동의를 구분.

**유지 가치:** 과제 이후에도 돌아올 이유를 만든다. 장기적으로 과목별 반복 약점을 보여줄 수 있다.

**신뢰 가치:** 현재 갤러리 2개를 넘어, 동의받은 실제 사례와 실패 사례를 함께 설명할 기반이 된다. 분석에는 과제 유형별 오차·범위 포함률·반복 실행 변동을 사용한다. 단순 상관계수나 일부 성공 사례만으로 정확도를 홍보하지 않는다.

교수의 성향을 알아냈다고 주장하지 않는다. 표본이 적을 때는 참고 코멘트로 사용하고 자동 점수 보정을 서두르지 않는다. 모델·프롬프트를 바꿀 때는 따로 보관한 검증 과제로 확인한다.

### 6순위. 튜터·스터디 그룹용 소규모 워크스페이스

후속 확장 후보는 과외 교사·라이팅 튜터다.

- 튜터가 루브릭을 배포하고 학생이 자기 초안을 사전 점검.
- 튜터가 허용된 결과를 보고 가장 중요한 문제에 코멘트.
- 초대·활성 학생·공통 약점을 보는 작은 대시보드.
- 학생 수 또는 포함 평가량을 기준으로 별도 상품을 검증.

처음부터 학교 전체 LMS를 만들면 판매·권한·데이터·운영 범위가 크게 늘어난다. 먼저 소수 튜터의 실제 사용과 지불 의사를 확인한다. 학생 Pro 무제한 상품에 대량 채점 비용을 그대로 포함하지 않는다.

## 6. 경쟁 제품을 고려한 포지셔닝

[Grammarly 공식 AI Grader 안내](https://support.grammarly.com/hc/en-us/articles/38552360525837-AI-Grader-user-guide)는 루브릭·과제 정보 기반 피드백, 문단별 제안, 점수 추정, 기본 기준 검토와 Free의 하루 1회 제한 검토를 설명한다. 따라서 “AI가 루브릭으로 채점한다”는 기능만으로 독점적인 차별성을 주장하기 어렵다.

[EssayGrader 공식 가격 안내](https://www.essaygrader.ai/pricing)는 교육자 중심으로 루브릭 라이브러리, 글쓰기 성장 추적과 LMS 연결을 판매한다. 교사 시장은 학생 시장과 구매 이유가 다르며, 그 무료 횟수나 가격을 RubriCheck에 그대로 적용할 근거는 없다.

권장 약속:

> 제출 전에 내 루브릭에서 놓친 부분을 찾고, 수정본이 어떻게 달라졌는지 확인한다.

세부 경쟁력은 **빠른 시작, 내 루브릭의 정확한 해석, 원문에 연결된 근거, 반복 수정 기록, 실제 피드백으로 확인되는 신뢰**에서 검증해야 한다. 이것들이 다른 제품에 전혀 없다고 주장하는 것은 아니다.

| 무료 | 0 | 총 3회 체험, 기본 피드백과 우선순위 일부 |
| Pro 월간 | $7.99/월 | 무제한 평가, Strict, 상세 피드백, 재작성 제안 |
| Pro 연간 | $59.99/년 | 같은 Pro 기능, UI에서 약 37% 절약 안내 |
| 충전 | 10회 $4.99 / 25회 $9.99 / 60회 $19.99 | 평가용, Strict·상세 결과, 재작성 제외 |

가격 표시는 [운영 가격 페이지](https://rubricheck.com/pricing)와 캡처 기준이며, 실제 결제 통화·세금·Stripe 청구 설정을 별도로 확인한 것은 아니다.

권장 원칙:

1. 가격부터 낮추지 않는다. 입력 유실·첫 체험·구독 가치·전환 계측을 먼저 개선한다.
2. Free는 좋은 피드백을 믿을 수 있게 만드는 체험, Top-up은 가끔 있는 과제, Pro는 학기 동안 반복 수정·과목별 관리로 설명한다.
3. Pro의 차이를 “무제한”보다 “이전 과제부터 다음 과제까지 이어지는 수정 기록과 코칭”으로 보여준다.
4. 가격 페이지에 Free/Top-up/Pro의 차이와 실제 결과 예시를 함께 제공한다. 현재 탭을 오가며 비교해야 하는 부담을 줄인다.
5. 동일 과제의 단순 재열람·결제 후 복구는 새로운 평가 구매로 취급하지 않는 방향을 검토한다. 신규 재평가와 상세 추가 분석의 차감 규칙은 명확히 보여준다.
6. 학기권·일시정지는 실제 해지 사유에서 방학·학기 종료가 자주 나올 때 검증한다. `semester`라는 내부 plan 값이 있지만 현재 공개 결제 선택지는 월간·연간이다. 처음부터 상품 수를 더 늘릴 이유는 약하다.
7. 60회 충전이 일부 사용자에게 긴 기간 충분할 수 있다. 이것이 구독을 잠식하는지, 원래 구독하지 않을 사용자의 추가 매출인지 코호트별 매출·비용·후속 전환으로 구분한다.

Pro가 무제한인 만큼 수익은 결제 건수만으로 판단할 수 없다. 성공·실패 평가의 입력/출력 사용량, OCR, 재시도, 저장 비용을 기록한다. 기존 7일 루브릭 구조화 캐시는 이미 있으므로 이를 새 기능처럼 제안하지 않는다. 버전 보관으로 중복 분석을 줄이는 방향을 검토한다.

## 8. 6–8주 실행 순서

개발자 1명이 기존 스택을 잘 안다는 가정의 실행 초안이다. 특히 계정별 저장과 파일 관리가 예상보다 크면 1순위 기능을 더 작게 나눈다.

### 1주차: 전환 동선과 기준선

- 입력 유실 해결, 무료 실패 반환 정책 정리.
- 핵심 이벤트와 평가 비용 기록.
- 홈 상단 무료 범위, 첫 결과 예시, 가격 비교 개선.
- 실제 사용자 5명 정도와 자발적 사용 관찰을 모집할 계획 수립. 이번 분석에서 연락하거나 인터뷰하지 않았다.

### 2–3주차: 첫 체험과 과제 저장

- 미리 계산한 예시 체험.
- 계정별 과제 1개 저장, 입력·루브릭 재사용.
- 현재 과제를 보존하는 업그레이드 복귀.
- 무료 3회를 초안→수정본→최종 점검으로 안내.

### 4–6주차: 수정 전후 비교 MVP

- V1/V2 저장과 기준별 비교.
- 개선 체크리스트와 해결 여부.
- Pro의 여러 과제·장기 이력 구분.
- 같은 조건의 평가 안정성 검증.

### 7–8주차: 검증된 사용 흐름 확대

- 루브릭 시작 링크와 유입 측정.
- 실제 성적 추가의 작은 입력 화면.
- 지표를 보고 루브릭 없는 시작 기능, 문단 코칭, 튜터 파일럿 중 하나를 선택.

**3개만 구현한다면:** 입력을 보존하는 로그인 전 예시 체험, 과제별 저장, 수정본 비교. 이 세 가지로 첫 체험·반복 사용·구독 이유를 함께 검증한다. 계측은 세 기능 모두에 포함한다.

## 9. 성공을 판단하는 방법

성장 구조:

`관련 방문 → 첫 평가 완료 → 실제 수정·재평가 → 다음 과제 사용 → 유료 전환 → 갱신`

현재 자료만으로 가장 큰 이탈 구간을 확정할 수 없다. 아래 순서로 기준선을 만든다.

| 목표 | 주 지표 | 함께 확인할 지표 |
|---|---|---|
| 사용자 증가 | 주간 첫 평가 완료 사용자 | 방문 경로, 첫 평가 시간·오류, 획득 원가 |
| 제품 가치 | 동일 과제 7일 내 재평가 사용자 비율 | 실제 수정 여부·유용성 피드백 |
| 반복 사용 | 첫 평가 사용자 중 30일 내 두 번째 과제 사용자 비율 | 학기·국가·과제 유형 |
| 구독 전환 | 첫 평가 후 14일 내 신규 Pro 비율 | paywall→checkout→결제 성공 |
| 유지 | 유료 2개월차 유지율 | 해지 이유, 학기권·방학 영향 |
| 수익성 | 코호트별 매출−변동 비용 | 모델/OCR·결제 수수료·환불·지원 비용 |

무료 체험 확대는 첫 평가 완료를 늘려도 결제나 기여이익을 떨어뜨릴 수 있다. 추천 보상도 가입 건수 대신 실제 사용과 비용을 본다.

최근 검색 클릭 424회/28일만 보면 여러 A/B 실험을 동시에 돌려 구독 차이를 확정하기에는 표본이 적을 가능성이 높다. 전체 유입을 먼저 확인하고, 초기에는 한 가지 변화씩 사용성 관찰과 코호트 데이터를 모은다. 짧은 기간의 몇 건 차이를 확정적 개선으로 선언하지 않는다. 학사 일정과 이미 존재하던 검색 증가 추세도 기록한다.

MRR은 월간 구독과 연간 구독을 월 기준으로 환산해 계산한다. 충전 매출은 별도 일회성 매출로 보고, 이를 MRR에 섞지 않는다. 원가가 확인되기 전에는 구체적인 매출 상승률이나 안정적인 마진을 예측하지 않는다.

## 10. 지금은 뒤로 미룰 기능

- **전면 자동 에세이 작성:** 현재의 검토·수정 가치를 흐리고 일반 생성 도구와 비교되기 쉽다. 원문에 근거한 코칭부터 검증한다.
- **일반 챗봇:** 과제·기준·원문·수정 이력에 연결되지 않은 대화는 추가 구독 이유가 약하다.
- **독립 AI 탐지·Humanizer:** 코드의 Hidden AI text 경고는 문서 내 지시문 경고다. 일반적인 AI 작성 여부 탐지로 홍보할 근거가 없으며 성장 주력 기능으로 확대하지 않는다.
- **네이티브 모바일 앱:** 웹 입력과 재사용이 먼저다. 사진 입력은 이미 있다.
- **대규모 LMS·학교 영업:** 개인 학생의 반복 사용과 작은 튜터 수요를 먼저 검증한다.
- **많은 언어·시험별 페이지:** 영어 검색 의도에서 실사용 전환을 만든 후 실제 수요로 확장한다.
- **상품·할인 종류 확대:** 월간·연간·충전이 이미 있다. 지속적인 제품 가치와 명확한 비교를 먼저 만든다.

## 12. 이번 분석의 산출물

애플리케이션 기능이나 결제 정책은 변경하지 않았다. `doc/growth/`에 보고서, 공개 사이트 확인 스크립트, 캡처와 재집계 자료를 추가했다. 브라우저 스크립트는 이 PC에 설치된 Playwright 패키지를 찾아 사용하는 분석용 도구이며 제품 실행 의존성은 아니다.

검증: 공개 UI·6개 안내 페이지·요금제 탭·모바일 가로 넘침 없음 확인, 입력 유실 재현, 원본 검색 통계 재계산, 점수 후처리 합성 데이터 검증. 인증 이후 전체 평가와 실제 결제 완료 흐름은 실행 검증하지 않고 코드로 검토했다.
