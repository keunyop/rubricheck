# 가격 확인·결제 복귀 시 작업 보존

## 동작

- 텍스트, 입력 방식, 채점 모드를 현재 탭에 자동 저장한다. 복원 유효기간은 24시간이다.
- 선택한 파일은 탭별 키로 브라우저 IndexedDB에 보관한다. 가격 페이지 이동 전에 저장 완료를 기다리며, 저장할 수 없으면 현재 페이지를 유지한다. 만료 파일은 저장소 접근 시 정리한다.
- 결과는 탭별 복원본과 기존 localStorage 복원본을 함께 유지한다.
- 서버는 평가 성공 시 원래 구조화 루브릭, 추출된 과제 텍스트, 결과를 기존 Redis에 24시간 보관한다. 결제를 시작하면 해당 과제를 7일간 보관한다. 원본 파일은 서버 복귀 저장소에 보관하지 않는다.
- UUID 결과 ID를 Pricing, Stripe metadata, 성공·취소 복귀 URL에 연결한다. 서버는 로그인 계정의 이메일 해시로 소유권을 확인한다.
- 결제 확인 후 별도 상세 분석 API가 원래 과제를 분석한다. 원래 결과 ID·점수·요약을 유지하며 서버에서 생성한 상세 피드백을 추가한다. UI만 잠금 해제하지 않는다.
- 연결된 무료 결과의 상세 분석은 구매에 포함하며 추가 평가 크레딧을 차감하지 않는다. 이후 새로운 평가에는 기존 사용량 정책을 적용한다.
- 동일 결과의 진행 중이거나 완료된 Checkout Session을 재사용한다. 동시 생성은 Stripe idempotency key로 제한한다. 상세 분석에는 Redis 잠금과 결과 캐시를 적용한다.
- 크레딧 지급은 저장소의 멱등 처리를 먼저 실행하고 처리 완료 표시를 나중에 기록한다. 지급 전 실패·응답 유실·웹훅과 브라우저 확인의 동시 실행에서 중복 지급을 방지한다.
- 서버 복귀 저장에 실패해도 이미 성공한 평가를 실패로 바꾸거나 잘못 환불하지 않는다. 화면에 복귀 저장 불가 안내를 표시한다.
- 결제 확인 또는 상세 분석 실패 시 복귀 session ID를 유지하여 새로고침으로 재시도한다.

## 검증

- `npm run test:all`: 기존 테스트와 추가 회귀 테스트 70개 통과.
- Chromium 브라우저 시나리오 7개: 텍스트 왕복·새로고침·뒤로 가기, 파일 복원 후 실제 FormData 제출, 원래 결과 업그레이드, 결제 확인 지연·분석 실패 재시도, 취소 복귀·탭 분리, 저장 차단, 손상·만료 데이터.
- `npx tsc --noEmit`, 운영 빌드, 앱·라이브러리·테스트 스크립트 lint 확인.
- 전체 `npm run lint`에는 기존 미추적 `doc/growth/browser-audit.cjs`, `public-flow-audit.cjs`의 require import 오류 6개가 남아 있다. 해당 사용자 파일은 수정하지 않았다.
- 기존 루브릭 캐시 테스트의 단일 기준 모의 데이터를 현재 스키마의 최소 2개 기준 조건에 맞췄다. Node 테스트 실행기에는 Next.js 확장자 생략 import 해석을 추가했다.

브라우저 재실행:

```powershell
npm.cmd run dev -- --hostname 127.0.0.1 --port 3100
# 별도 터미널: 설치된 Playwright의 index.mjs 경로를 지정한다.
$env:PLAYWRIGHT_MODULE = '설치된 playwright-core/index.mjs 절대 경로'
npm.cmd run test:recovery:browser
```

브라우저 테스트는 계정·결제·분석 API를 모의 응답으로 대체한다. 서버 테스트도 외부 서비스에 실제 요청하지 않는다. 결과는 `.recovery-browser-results.json`에 기록된다.

## 실제 Stripe 테스트에서 확인할 항목

실제 Stripe 결제·웹훅과 AI 모델을 연결한 종단 간 테스트는 실행하지 않았다. 배포 전 테스트 모드에서 아래 항목을 확인해야 한다.

1. 무료 결과 ID를 기록하고 Top-up / Pro 각각 결제를 완료한다.
2. 같은 ID의 상세 결과로 돌아오고 원래 입력·파일 및 점수가 유지되는지 확인한다.
3. 성공 URL 새로고침, 복수 탭 요청, 동일 웹훅 재전송에서 Checkout Session / PaymentIntent / 구독이 추가 생성되지 않는지 확인한다.
4. Top-up은 한 번만 지급되고, 원래 결과의 상세 분석 때문에 크레딧이 추가 차감되지 않는지 확인한다.
5. 상세 분석 중 새로고침하거나 모델 요청을 실패시켜도 동일 ID로 재시도하고 중복 차감하지 않는지 확인한다.
6. 결제 취소 및 지연 결제 확인에서 원래 작업으로 복귀하는지 확인한다.

기존 Redis 설정을 사용하며 DB 마이그레이션은 없다.
