# 2026-11-14 첫 결과 확인율 90%와 확인 사용자 2배

- 모드: owner experiment 후속. 사용자가 두 목표를 함께 확정했다. 오늘 콘텐츠는 이미 게시되어 다시 발행하지 않는다.
- 기준선: Vancouver 현지 2026-10-31~11-06의 7일 첫 관측 평가 시작 코호트. 성공 평가와 연결된 결과를 각자의 시작 후 7일 안에 본 고유 행위자를 센다. 게스트와 계정을 비모호한 연결에 한해 합친다. 관측 기간이 끝난 코호트만 판정한다. [재현 쿼리](../queries/first-result-7d.sql)의 UTC 경계를 창마다 교체한다. 실제 분자·분모와 출처별 집계는 Git 제외 `.growth-local/owner/2026-11-14-dual-activation-goal.json`에 있다.
- 두 종료 지표: **7일 내 유효 결과 확인율 90% 이상**과 **같은 길이의 코호트에서 유효 결과를 확인한 고유 사용자 2배 이상**. 두 조건을 동시에 충족해야 한다. 같은 정의의 주간 첫 평가 시작자 규모를 선행 지표로 둔다. 목표 달성에 필요한 정확한 인원 기준선과 운영 선행 목표는 비공개 owner 기록에 보관한다. 단순 방문, 가입, 완료 이벤트나 전체 결과 열람 건수를 확인 사용자로 세지 않는다.
- 목표 시점: 2027-01-30까지 두 번 연속 완전히 성숙한 7일 코호트에서 두 조건을 확인한다. 마지막 비교 창은 2027-01-16~01-22에 시작한 사용자이며, 01-29 이후 7일 후속 관측을 마치고 판정한다. 목표 시점은 실행 일정이지 달성 예측이 아니다.
- 기준의 한계: first-party 수집은 2026-10-29 시작이므로 `첫 관측`은 평생 첫 사용이 아니다. 동의·식별·내부/테스트 제외의 포괄률은 아직 미확인이다. 기준선은 한 주의 소표본이며 계절성과 검색 순위가 영향을 준다. 성과 판정 전에 동일한 포괄률과 정의를 대조한다.
- 현지 시간: 2026-03-08 이후 Vancouver는 연중 UTC-07:00을 사용한다. 해당 코호트 경계는 2026-10-31 07:00Z 이상, 2026-11-07 07:00Z 미만이다. 현재 Supabase Postgres의 오래된 tzdata는 Vancouver 변환을 한 시간 잘못 계산하므로 성과 쿼리는 명시적 UTC 경계를 사용한다. [BC 정부 안내](https://news.gov.bc.ca/releases/2026AG0013-000209), [Supabase 공지](https://supabase.com/changelog/tzdata-local-time-vancouver-edmonton-casablanca).

## 실행 순서

1. **복구율:** 이미 배포한 입력·파일·루브릭·중복 진행·기타의 고정 실패 범주를 11/17에 처음 점검한다. 7일 복구 결과가 아직 성숙하지 않은 새 범주는 조기 성과로 쓰지 않는다. 게스트↔계정 연결, 동의, 내부·테스트 제외와 완료→결과 확인 연결을 함께 확인한다. 가장 큰 실제 실패 원인 하나를 택해 재시도/안내/기존 결과 복귀 중 해당하는 작은 수정만 구현한다. 11/21 출시 준비를 판정하며 표본이 부족하면 관찰을 연장한다.
2. **시작자 규모:** 같은 코호트의 첫 평가 시작과 유효 결과 확인을 `first_touch` 출처·랜딩별로 보되, 소표본을 인과 효과로 해석하지 않는다. 현재 관측에는 검색 유입과 홈 진입이 집중되어 있다. 11/17에 GSC의 *같은 완결 기간* 검색어×페이지·국가별 근거와 제품 CTA·색인을 확인해 기존 홈/도구 랜딩 또는 실용 콘텐츠 중 한 가지 검색 유입 개선을 선정한다. 메타데이터가 빠진 과거 CSV를 전환율 분모로 섞지 않는다. 이미 게시한 글의 7일 색인·링크와 28일 검색→첫 평가 경로를 점검한다.
3. **주간 판정:** 11/24까지 첫 출시가 이루어지면 12/10에 출시 후 완전히 성숙한 첫 7일 코호트를 읽는다. 실제 출시 시각이 늦어지면 첫 판정일도 같은 만큼 미룬다. 매번 같은 UTC 경계·고유 행위자 정의로 시작자 수, 확인 사용자 수, 확인율을 함께 기록한다. 신규 실패 범주, 첫 시도 24시간 확인, 평가 품질·오류, 중복 과금, 후속 별도 평가를 보호·진단 지표로 둔다. 동의/식별 포괄률이 흔들리거나 평가 품질이 악화되면 목표 숫자만으로 채택하지 않는다.
4. **확대 판단:** 12/12에 콘텐츠별 완결 검색·첫 결과 경로를 검토하고, 12/19에 중간 목표 대비 시작자·복구율을 대조한다. 2027-01-30에 두 연속 성숙 코호트와 품질 보호 지표로 목표를 판정한다. 검색 노출·클릭과 결과 확인 사용자 증가는 별도로 기록하며 단순 전후 차이를 실험의 인과 효과로 단정하지 않는다.

## 이번 실행의 완료와 한계

- 동일한 7일 기준선을 읽기 전용으로 재계산하고 두 목표·주간 선행 목표·판정 창을 확정했다. 출처·랜딩별 경로를 확인해 유입 개선의 첫 검토 대상을 검색과 홈으로 정했다. 비공개 수치는 Git 제외 owner 기록에 저장했다.
- 실패 원인 고정 범주 계측은 [이전 실행](2026-11-14-activation-plan.md)에서 production 검증됐다. 이번 후속 실행은 목표와 의사결정 규칙을 확정한다. 확인율 또는 사용자 수의 실제 증가는 아직 관측되지 않았다.
