# 비공개 과제 수정 실험실

## 테스트 주소와 적용 순서

- 로컬: http://localhost:3000/lab/assignments (개발 서버 포트에 맞춰 변경)
- 현재 작업 세션의 개발 서버: http://127.0.0.1:3107/lab/assignments
- 배포 후: https://rubricheck.com/lab/assignments
- 운영 메뉴와 sitemap에는 링크를 추가하지 않았습니다. 페이지는 noindex/nofollow이며, 서버가 페이지와 모든 API에서 테스터 권한을 검사합니다.
- 기존 이메일 인증 로그인을 완료한 뒤 위 주소로 돌아오세요. 기본 관리자 계정과 서버 환경변수 `ASSIGNMENT_LAB_EMAILS`의 이메일만 접근할 수 있습니다. 쉼표로 여러 이메일을 지정할 수 있습니다. URL을 아는 것만으로는 접근할 수 없습니다.
- 실험실 전용 SQL은 로컬 PostgreSQL에서 검증했습니다. **운영 Supabase 적용과 배포는 이 작업에서 실행하지 않았습니다.**

### 활성화

1. Supabase SQL Editor에서 [assignment_lab.sql](../supabase/assignment_lab.sql)을 실행합니다. 신규 `lab_*` 테이블·함수만 추가하며 기존 평가·결제 테이블은 변경하지 않습니다. 재실행할 수 있습니다.
2. 기존 `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, 로그인 세션 비밀키, `OPENAI_API_KEY`, `STRUCTURE_MODEL`, `EVALUATION_MODEL`을 사용합니다.
3. 필요하면 서버 전용 `ASSIGNMENT_LAB_EMAILS`를 지정합니다. 관리자에게는 별도 설정이 필요 없습니다.
4. Next.js 앱을 배포합니다. 평가 API의 최대 실행 시간은 300초입니다. 호스팅 환경이 이 시간을 지원해야 합니다.
5. 관리자 이메일로 기존 홈 화면에서 로그인 후 실험실 URL을 엽니다. DB가 아직 적용되지 않았다면 실험실에만 설정 오류가 표시됩니다.

공개 전에는 인증된 일반 사용자를 허용하도록 `labEmailAllowed` 정책을 바꾸고 메뉴를 추가해야 합니다. 이번 변경은 공개 전환을 자동으로 하지 않습니다.

## 제공 범위

- 과제 이름, 원문 루브릭, 첫 초안을 서버에 저장합니다. 초안 평가는 저장 다음 단계이므로 모델 실패 시에도 과제를 다시 열 수 있습니다.
- 같은 과제의 V1/V2 및 Pro 후속 버전, 기준별 범위와 추정 점수 변화, 이전·현재 피드백을 확인할 수 있습니다.
- 개선 항목을 열면 이유, 필요한 근거, 확인 질문, 재평가 판정을 봅니다.
- 수정본 텍스트 붙여넣기와 PDF/DOCX/TXT 업로드를 지원합니다. 파일은 최대 3 MB, 추출 텍스트는 필드당 60,000자입니다. 원본 바이너리는 저장하지 않고 추출된 텍스트를 저장합니다.
- 무료: 보관 중인 과제 1개, 성공한 평가 V1/V2. 삭제하면 다른 과제를 만들 수 있습니다.
- Pro: 보관 중인 과제 최대 100개, 과제당 최대 50개 버전. 실험실 운영 한도이며 기존 요금제 소개나 결제 동작을 변경하지 않습니다.
- 평가 실패는 성공 버전 한도를 소모하지 않습니다. 기존 평가 잔액·크레딧을 차감하지 않습니다.
- 다운로드(JSON)와 과제 전체 삭제는 요금제·버전 한도와 무관합니다. Pro 만료 후에도 기존 기록을 읽고 내보내고 삭제할 수 있습니다.
- 장기 이력은 자동 만료 없이 삭제할 때까지 보관합니다. 과목별 약점 대시보드, 문단 강조, 인라인 편집기는 후속 단계입니다.

## 비교의 의미

- 구조화한 루브릭과 mode는 과제 내에서 고정됩니다.
- 각 run에는 루브릭 버전 ID, mode, 모델 식별자, 평가·코칭 프롬프트 지문, 구조화 모델·버전, 점수 계산 버전을 저장합니다.
- 공유 평가 프롬프트의 실제 내용이 달라지면 지문이 바뀝니다. 구조화·점수 계산 정책을 바꿀 때는 해당 버전도 갱신해야 합니다. 모델 ID가 별칭이면 공급자의 내부 모델 변경까지 자동 탐지할 수는 없습니다.
- 모델·프롬프트 등 조건 변경을 화면에 표시하고 점수 차이를 직접 비교하지 않습니다.
- 동일한 정규화 텍스트(양끝 공백·개행 형식 정리)와 조건은 기존 결과를 반환합니다. 새로운 버전이나 모델 호출이 생기지 않습니다. 과거 V1과 같으면 V1이 다시 열릴 수 있습니다.
- 평가 모델에는 이전 점수나 체크 상태를 주지 않습니다. 점수는 내려가거나 같을 수도 있습니다.
- 체크박스는 사용자의 작업 표시입니다. AI 해결 판정과 구분합니다. 각 이전 항목은 새 버전에서 다시 검토하며, 일치하는 현재 원문 인용이 없는 해결 판정은 “Needs review”로 바꿉니다.
- 해결된 항목이 다시 문제가 되면 같은 작업 ID를 유지하며 새 문제로 표시합니다.
- 형식에 맞지 않는 모델 코칭 출력은 1회 복구를 시도하고, 계속 실패하면 버전 전체를 저장하지 않습니다.
- 화면의 수치는 AI 추정 범위이며 실제 성적 향상이나 통계적 신뢰구간을 뜻하지 않습니다.

## 저장·권한·실패 처리

- 검증된 서명 로그인 세션의 이메일을 SHA-256으로 매핑하고 `lab_users.id` UUID를 소유권 기준으로 사용합니다. 결제 고객 ID, 클라이언트 이메일, 임의 owner/plan 값은 소유권을 부여하지 않습니다.
- 테이블: `lab_users`, `lab_assignments`, `lab_rubric_versions`, `lab_evaluation_runs`, `lab_revision_tasks`, `lab_events`.
- 모든 테이블에 RLS를 켜고 anon/authenticated의 직접 접근 및 RPC 실행을 차단합니다. 서비스 역할만 RPC를 호출하며 함수 내부에서도 소유권을 확인합니다.
- 생성·버전 제한은 DB 잠금 안에서 검사합니다. 사용자당 한 평가만 진행되고 시간당 20회 시작 한도가 있습니다.
- 평가 예약은 고유 토큰과 6분 임대를 사용합니다. 과제·버전·작업 저장은 트랜잭션으로 수행하고 중복 커밋은 같은 run을 반환합니다.
- 260초 생성 제한, 실패 시 본인 예약만 해제, 응답 유실 시 동일 저장 1회 재시도가 있습니다. 프로세스가 강제 종료되면 임대 만료 후 재시도할 수 있습니다.
- 평가 중 삭제된 과제는 늦게 온 모델 결과로 복구되지 않습니다.
- 다운로드는 소유권 확인을 거치며 초안·루브릭·결과·체크 상태·과제 이벤트를 포함합니다.
- 과제 삭제는 연결된 루브릭·버전·체크리스트·피드백·이벤트를 함께 삭제합니다. 최소 사용자 식별 매핑은 남습니다.
- 응답은 private/no-store이며, 원문·자격 증명·DB 오류 상세를 실험실 로그나 오류 응답에 포함하지 않습니다.

## 지표

[assignment_lab_metrics.sql](../supabase/assignment_lab_metrics.sql)은 관리자용 읽기 전용 쿼리입니다.

- 같은 과제 재평가율: V2 이상 과제 / V1 이상 과제.
- 30일 내 두 번째 과제: 첫 생성 후 30일 관찰이 끝난 사용자에서 측정합니다.
- 실제 수정 후 유용성: 텍스트가 직전 버전과 달라진 V2 이상의 피드백만 받습니다. 같은 run의 응답은 갱신되며 중복 집계되지 않습니다.
- 재평가 여부와 현재 Pro 비율: 검증된 사용자 매핑과 기존 결제 원장을 연결한 기술적 비교입니다.
- 실제 구독 전환·유지율은 별도의 시점별 구독 코호트 분석이 필요합니다. 선택 편향이 있어 위 비율 차이를 인과효과로 해석하면 안 됩니다.
- 삭제된 과제는 이벤트도 삭제되므로 지표에서 빠집니다. 무료 삭제 후 재생성 및 관리자 테스트 데이터도 해석 시 고려해야 합니다.

## 검증 방법

- `npm run test:all`: 기존 테스트와 실험실 API·비교·코칭 테스트 전체.
- `npm run test:lab:db`: 별도 로컬 PostgreSQL에 migration을 적용하고 SQL 불변조건 및 실제 8개 동시 요청을 검증합니다. 운영 DB URL은 거부합니다. 기본 연결은 `postgresql://lab_test@127.0.0.1:55439/postgres`이며 `LAB_TEST_DATABASE_URL`, `PSQL_PATH`로 변경할 수 있습니다. 테스트 DB에 anon/authenticated/service_role 역할이 필요합니다.
- `npm run test:lab:browser`: 로컬 서버에서 UI/API 응답을 모의 처리해 생성·복원·수정 업로드·실패·비교·다운로드·삭제·모바일·비공개 노출을 검사합니다. `PLAYWRIGHT_MODULE`로 설치된 Playwright 모듈을 지정할 수 있습니다. 기본 포트 3107.
- `LAB_LIVE_AI=1 npm run test:lab:live`: 실제 모델과 별도 로컬 DB를 사용하는 합성 과제 통합 테스트입니다. 모델 호출 비용이 발생합니다. 운영 Supabase에는 쓰지 않습니다.
- `npm run test:recovery:browser`: 기존 평가 및 결제 복귀 화면 회귀 검사.
- `npm run build`, `npm run test:seo`, 타입 검사, 신규 파일 린트.
- 화면 캡처: [데스크톱](assignment-lab/desktop.png), [모바일](assignment-lab/mobile.png). 합성 테스트 데이터입니다.

전체 린트에는 변경 전부터 있던 `doc/growth/browser-audit.cjs`, `doc/growth/public-flow-audit.cjs`의 CommonJS import 오류 6개가 있습니다. 해당 사용자 파일은 수정하지 않았습니다.
