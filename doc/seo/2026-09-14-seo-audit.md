### 집계 해석 시 주의점

- 사이트 전체 합계는 일별 차트의 **690클릭·5,553노출**을 사용했다. 국가·기기 합계도 이 수치와 일치한다.
- 페이지 합계는 **695클릭·7,389노출**이다. 사이트 단위와 페이지 단위 집계 방식이 다르므로 이를 사이트 전체 실적으로 대체하지 않았다. [Google의 집계 설명](https://support.google.com/webmasters/answer/7576553?hl=en)
- 검색어 표 합계는 **295클릭·2,120노출**로 전체를 모두 설명하지 않는다. 누락분을 특정 검색어·브랜드 유입으로 추정하지 않았다.
- 검색 노출 유형 테이블이 비어 있다고 해서 사이트에 구조화 데이터가 없거나 Google 검색에 노출되지 않는다는 뜻은 아니다.
- ZIP에는 검색어와 페이지를 교차한 데이터가 없다. 어떤 검색어의 노출이 어느 URL에서 발생했는지 연결하려면 Search Console에서 페이지 필터를 추가해야 한다.

## 3. 국가·기기와 AI 기능

미국은 241클릭·2,477노출, 말레이시아는 204클릭·479노출, 호주는 71클릭·835노출이다. 그 뒤는 캐나다 32클릭, 인도 23클릭, 영국 17클릭, 필리핀 16클릭이다. 한국은 36노출·0클릭이다.

기존 영어 콘텐츠와 영어 검색 수요를 우선 개선했다. 국가별 CTR 차이만으로 번역 페이지나 지역별 복제 페이지를 추가할 근거는 부족하다. 특히 말레이시아의 CTR 42.59%를 다른 국가에 그대로 적용하지 않는다.

AI 기능 노출은 전체 **1,258회**, 최근 28일 **710회**, 직전 28일 **244회**다. 페이지별 노출은 홈 1,169, 사용법 가이드 76, 과제 검사 55, AI 채점 50, 피드백 21회다. 페이지 합계 1,371회를 사이트 전체 합계로 사용하지 않았다. 국가별로는 미국 509, 말레이시아 190, 호주 161회, 기기별로는 데스크톱 972, 모바일 272, 태블릿 14회다.

이 ZIP에는 클릭수가 없으므로 AI 기능의 클릭·CTR·전환율을 계산할 수 없다. 웹 검색 노출에 AI 기능 노출을 더해 별도 전체 노출을 만들지도 않았다. AI 기능 최적화는 명확한 답변, 구체적 예시, 정상 색인·내부 링크를 중심으로 진행했다. Google은 별도의 AI 전용 파일이나 특수 schema가 필요하지 않다고 안내한다. [Google AI 기능 안내](https://developers.google.com/search/docs/appearance/ai-features)

Google의 [사용자 중심 콘텐츠 가이드](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)를 기준으로 내용을 작성했다. FAQ 리치 결과는 2026-05-07부터 종료됐고, 해당 문서는 6월 제거되었다. [Google 변경 이력](https://developers.google.com/search/updates#june-2026)

사이트맵의 priority/changefreq는 Google이 무시하므로 제거했고, lastmod는 유의미한 실제 변경일만 나타내도록 했다. [사이트맵 공식 문서](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)

`noindex`가 관측되려면 크롤링을 허용해야 한다. 관리자 인증 로직은 기존대로 유지되며 robots.txt를 접근 권한 제어로 사용하지 않는다. [noindex 공식 문서](https://developers.google.com/search/docs/crawling-indexing/block-indexing)

## 5. 검증

- `npm run build`: 프로덕션 빌드 및 TypeScript 검사 통과. 공개 페이지는 정적 HTML로 생성된다.
- `npm run lint`: 오류 0건. 기존 `lib/evaluationNormalization.ts` 3건, `src/lib/adminDashboard.ts` 1건의 미사용 변수 경고가 있다.
- `npm run test:seo`: 공개 페이지 **13개 전부 통과**. 로컬 프로덕션 서버를 자동 시작·종료하며 다음 항목을 실제 HTTP로 검증했다: 사이트맵의 공개 URL, 200 응답, 고유 제목·설명, H1, canonical, OG·Twitter, 내부 링크, JSON-LD, Breadcrumbs, 1200×630 PNG, noindex, 리디렉션, 404.
- 초기 HTTP 검사에서 내부 포트가 canonical 리디렉션에 남는 문제를 발견해 수정했다. 수정 후 프로덕션 빌드와 전체 HTTP 재검증이 통과했다.
- 생성된 공유 이미지(1200×630, 96,630바이트)의 텍스트·배치를 시각적으로 확인했다.
- `git diff --check`: 공백 오류 없음.
- 원본 ZIP 5개는 그대로 보존했다.

이 ZIP에는 Core Web Vitals나 Lighthouse 데이터가 없다. html2canvas 지연 로딩은 초기 번들의 불필요한 코드를 줄이기 위한 변경이며, LCP·INP·CLS 또는 검색 순위가 얼마나 개선됐다고 주장하지 않는다. 실제 성능은 배포 후 현장 데이터로 평가해야 한다.

## 6. 배포 후 필요한 작업

1. 변경된 코드를 운영 환경에 배포한다. 이번 작업에서는 운영 배포, Git push, DNS 수정 또는 Search Console 제출을 실행하지 않았다.
2. 운영 `/sitemap.xml`, `/robots.txt`, `/essay-rubric-checker`를 확인하고 기존 사이트맵 주소를 Search Console에서 재제출한다.
3. URL 검사에서 홈, 에세이 검사, AI 채점, 과제 검사, 피드백 페이지, 사용법 가이드의 라이브 테스트를 진행한다. canonical과 색인 허용 상태를 확인한 뒤 갱신된 주요 페이지의 색인을 요청한다.
4. Coverage의 ‘크롤링됨 — 현재 색인이 생성되지 않음’ 세부 보고서에서 실제 URL을 확인한다. 해당 URL의 응답, canonical, Google 선택 canonical, 최종 크롤링일, 렌더링된 본문을 확인한다. 현재 ZIP에는 원인 URL이 없으므로 이번 변경으로 그 제외 건이 해결됐다고 단정하지 않는다.
5. ‘리디렉션이 포함된 페이지’의 실제 URL을 확인한다. HTTP·별칭 등 의도된 주소라면 정상 제외로 관리하고, 정상 페이지가 잘못 리디렉션된다면 대상을 수정한다.
6. `www.rubricheck.com` 도메인 설정을 확인한다. 이번 환경의 HTTPS 접근은 이름 해석에 실패했고 Windows DNS 조회도 NXDOMAIN을 반환했다. www 주소를 지원하려면 배포 서비스에 해당 도메인·인증서를 등록하고 서비스가 제시하는 DNS 레코드를 설정한 뒤, apex 도메인으로 영구 리디렉션되는지 확인한다. 도메인 설정 없이 앱의 www 리디렉션 코드만으로는 해결되지 않는다.
7. Breadcrumbs는 배포된 가이드 URL을 Rich Results Test로 검증한다. 기존 4개 유효 항목과 새 크롤링 결과를 비교한다. 구조화 데이터가 유효해도 리치 결과 노출은 보장되지 않는다.

## 7. 성과 측정

배포일을 기록하고 배포 후 28일과 배포 전 28일을 같은 검색 유형·국가·기기 조건으로 비교한다. 이번 파일의 최근 28일 기준선은 **424클릭, 2,693노출, CTR 15.74%**, AI 기능 **710노출**이다. 실제 배포일이 늦어지면 기준 기간을 다시 잡는다.

홈의 `rubric checker` 성과를 유지하는지, 에세이 페이지가 색인되고 관련 검색어 노출·클릭을 얻는지, AI 채점·과제 검사·피드백 페이지의 CTR이 같은 조건에서 개선되는지를 우선 확인한다. 검색어와 페이지를 함께 필터링해 URL 간 중복 노출과 유입 변화를 살핀다. 국가·기기 구성 변화나 학사 일정에 따른 수요 변화를 코드 수정의 효과로 혼동하지 않는다.

색인 재처리와 검색 실적 반영은 Google의 크롤링·선택에 달려 있다. 이 문서는 구현과 검증 결과를 기록하며 특정 순위·클릭 증가를 보장하지 않는다.
